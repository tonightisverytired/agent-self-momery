# dnamemory 系统设计与系统架构设计

> 版本：v0.4.0 设计稿（基于 0.3.0 MVP）  
> 适用范围：长期个人智能体记忆系统  
> 核心原则：保留现有多路召回与治理基础设施，引入 Memory State、Evidence、Belief、Temporal Chain 和 Coherent Context 层，降低对 LLM 推理的依赖。

---

## 1. 设计目标

### 1.1 现有系统基础

0.3.0 已采用分层设计，核心为纯 Python 库，服务与 CLI 为薄壳；已有 retrieval、governance、extract、SQLiteStore、Embedder、Reranker、TimeBackend、GraphBackend 等模块。

### 1.2 本版本核心问题

现有架构更偏：

```text
Memory Retrieval
```

本版本升级为：

```text
Memory Runtime
```

重点解决：

1. 事实当前状态的确定性解析；
2. 事实与观点的类型隔离；
3. 证据可追溯；
4. 时间链恢复；
5. 多维记忆一致性；
6. 弱 LLM / 无 LLM 降级；
7. 召回结果从“Candidate”升级为“Coherent Memory Context”。

```text
├─────────────────────────────────────────────────────────────┤
```


## 4. 核心数据模型

### 4.1 Entity

实体表示长期稳定的对象：

```text
entity_id
name
kind
access_label
lifecycle
```

### 4.2 Event

事件表示发生过什么：

```text
Event
├── subject
├── predicate
├── target
├── occurred_at
├── source
├── confidence
└── evidence_ids
```

### 4.3 Fact

事实表示对象在某个有效时间段内的属性状态：

```text
Fact
├── entity_id
├── key
├── value
├── source
├── confidence
├── valid_at
├── invalid_at
├── superseded_by
└── evidence_ids
```

### 4.4 Belief

观点表示主体对某个命题的认知：

```text
Belief
├── subject
├── proposition
├── polarity
├── confidence
├── source
├── valid_at
├── invalid_at
├── superseded_by / related_belief
└── evidence_ids
```

注意：Belief 的历史变化不等同于 Fact 的覆盖。

### 4.5 Intent

```text
Intent
├── subject
├── proposition
├── status
├── valid_at
├── invalid_at
├── confidence
└── evidence_ids
```

建议 status：

```text
active
completed
cancelled
expired
superseded
```

### 4.6 Evidence

```text
Evidence
├── evidence_id
├── source_type
├── source_ref
├── conversation_id
├── message_id
├── observed_at
├── content_hash
├── trust_level
└── metadata
```

Evidence 不参与直接回答事实，而用于支持记忆状态和解释来源。

## 6. 写入架构

### 6.1 LLM 抽取路径

```text
Raw Text
  ↓
Extractor
  ↓
Candidate Memories
  ↓
Pydantic Validation
  ↓
Entity Resolution
  ↓
Evidence Binding
  ↓
Deterministic Governance
  ↓
SQLite Transaction
```

### 6.2 非 LLM 写入路径

```text
Structured API
  ↓
Pydantic
  ↓
Entity Resolution
  ↓
Evidence Binding
  ↓
Version / Conflict
  ↓
SQLite Transaction
```

两条路径进入同一治理层，避免“LLM 写入是一套规则，API 写入又是一套规则”。

## 7. Query Router

新增 `QueryRouter`。

### 7.1 Query Type

```text
current_state
history
timeline
change
why_change
comparison
semantic_recall
multi_hop
```

### 7.2 确定性优先

优先使用规则：

```text
当前 / 现在 / 目前
→ current_state

以前 / 历史 / 过去
→ history

什么时候 / 时间线 / 先后
→ timeline

为什么变 / 怎么变了
→ change / why_change
```

复杂场景可使用 LLM 辅助，但 QueryRouter 必须允许无 LLM 运行。

## 8. 检索架构

### 8.1 基础多路召回

保持 0.3.0：

```text
Time
Graph
Dense
Sparse
```

通过 RRF 融合。

### 8.2 新增候选扩展

RRF 后不是直接 Top-K，而是：

```text
RRF Candidates
 ↓
Entity Expansion
 ↓
Fact Version Expansion
 ↓
Temporal Neighbor Expansion
 ↓
Evidence Expansion
```

例如召回到：

```text
Fact(city=上海)
```

可以扩展到：

```text
历史 city 版本
相关搬迁 Event
相关 Belief
相关 Evidence
```

### 8.3 Candidate 与 Answer 分离

严格区分：

```text
Candidate Memory
```

与：

```text
Resolved Memory
```

Candidate 只说明“可能相关”；Resolved Memory 才允许进入最终上下文。

## 9. Memory State Resolver

这是本版本核心模块。

### 9.1 接口

```python
resolve(
    candidates,
    query_time=None,
    query_type="semantic_recall",
    entity_scope=None,
) -> MemoryState
```

### 9.2 输出

```python
MemoryState(
    current_facts=[],
    historical_facts=[],
    events=[],
    beliefs=[],
    intents=[],
    changes=[],
    conflicts=[],
    evidence=[],
    chains=[],
)
```

### 9.3 FactResolver

算法：

```text
过滤 deleted / tombstoned
 ↓
按 valid_at 定位时间有效集合
 ↓
按 source_rank
 ↓
按 confidence
 ↓
按 explicit_confirmation
 ↓
按 freshness
 ↓
输出 current / history / conflict
```

不要使用 Embedding 相似度决定当前事实。

### 9.4 BeliefResolver

Belief 以时间序列处理：

```text
B1
 ↓ change
B2
 ↓ reinforce
B2
 ↓ contradict
B3
```

最终形成 `BeliefTimeline`。

### 9.5 IntentResolver

根据状态和时间：

```text
active
completed
cancelled
expired
superseded
```

避免把过去计划当作现在意图。

## 10. Temporal Chain Builder

### 10.1 目标

将离散 Memory 节点恢复为有序链：

```text
Event A
 ↓
Event B
 ↓
Fact Change
 ↓
Belief Change
 ↓
Current State
```

### 10.2 构建输入

```text
occurred_at
valid_at
invalid_at
created_at
superseded_by
edges
memory_links
```

### 10.3 构建策略

第一阶段完全确定性：

```text
时间字段排序
 ↓
版本链连接
 ↓
显式 changes / supersedes 连接
 ↓
同实体邻接
 ↓
构建 Chain
```

第二阶段再增加可选 LLM 因果辅助。

### 10.4 时间排序规则

建议优先级：

```text
1. occurred_at
2. valid_at
3. observed_at
4. created_at
5. node_id 作为最终稳定 tie-breaker
```

同一时间必须有稳定排序，不允许依赖数据库返回顺序。

## 11. Evidence Validator

### 11.1 目标

验证：

```text
Memory → Evidence
```

### 11.2 检查

```text
Evidence 是否存在
Evidence 是否可访问
source_type 是否可信
content_hash 是否一致
时间是否合理
```

### 11.3 证据不足

若记忆没有足够 Evidence：

```text
confidence 降低
```

或：

```text
abstain
```

不得在最终 Context 中把 unsupported inference 伪装为 Fact。

## 12. Cross-Dimension Coherence

### 12.1 目标

验证：

```text
Event
Fact
Belief
Intent
```

是否能在同一时间上下文中同时成立。

### 12.2 示例

允许：

```text
Fact: 用户居住上海
Belief: 用户认为上海生活成本高
Intent: 用户考虑离开上海
```

不允许无解释地同时输出：

```text
Fact: 用户目前居住上海
Fact: 用户目前居住南京
```

应进入：

```text
Temporal Conflict
```

或：

```text
Source Conflict
```

### 12.3 输出

```python
CoherenceResult(
    consistent=True,
    conflicts=[],
    explanations=[],
)
```

## 13. Context Builder

最终交给 LLM 的不再是无结构 Top-K，而是结构化 Context。

```text
MemoryContext
├── current_state
├── recent_events
├── historical_changes
├── beliefs
├── intents
├── temporal_chains
├── evidence
└── conflicts
```

### 13.1 current_state

用于：

```text
“现在是什么？”
```

### 13.2 historical_changes

用于：

```text
“以前是什么？”
“发生过什么变化？”
```

### 13.3 temporal_chains

用于：

```text
“先发生什么，后发生什么？”
“为什么后来变成这样？”
```

### 13.4 evidence

用于：

```text
“依据是什么？”
```

LLM 只能在 `MemoryContext` 给出的状态和证据范围内组织语言。

## 20. 生命周期与治理

原有：

```text
active
 ↓ decay
archived
 ↓ forget
tombstoned
 ↓ compliance
deleted
```

继续保留。

但本版本增加：

```text
Memory State
```

生命周期状态与“事实有效状态”必须分离。

例如：

```text
lifecycle = active
fact validity = invalid
```

表示这条历史记忆仍然保留，但它已经不是当前有效事实。

不能将“invalid fact”直接删除。

## 21. Reflection 改造

原有 Reflection：

```text
月度摘要
主题簇
summarizes
part_of
```

继续保留，但增加原则：

```text
Raw Evidence
    ↓
Event / Fact / Belief
    ↓
Temporal Chain
    ↓
Summary
```

摘要是派生节点，不是原始事实的替代品。

摘要节点必须可以反向追溯：

```text
Summary
 ↓ summarizes
Events / Facts / Beliefs
 ↓ evidence
Original Evidence
```

## 22. 检索评分架构

RRF 继续作为候选融合方法：

```text
Time
Graph
Dense
Sparse
 ↓
RRF
```

但最终排序增加状态层特征：

```text
candidate_score
+ temporal_relevance
+ state_validity
+ source_reliability
+ evidence_strength
+ value_score
- conflict_penalty
```

不要直接把这些全部重新压成单一黑盒神经网络分数。

建议保留各维度分项分数，便于 explain 和测试。

---

## 23. 推荐评分结构

```python
MemoryScore(
    retrieval_score,
    temporal_score,
    validity_score,
    source_score,
    evidence_score,
    coherence_score,
    conflict_penalty,
)
```

最终可以形成：

```text
final_score =
    α * retrieval_score
  + β * temporal_score
  + γ * validity_score
  + δ * source_score
  + ε * evidence_score
  + ζ * coherence_score
  - η * conflict_penalty
```

其中权重全部在 `MemoryConfig` 构造阶段显式配置。

不要让权重依赖模型隐式学习，至少在 0.4.x 阶段保持可解释。

## 27. 错误码扩展建议

保留原有 E000~E011。

建议新增：

```text
E012  MEMORY_STATE_CONFLICT
E013  EVIDENCE_NOT_FOUND
E014  TEMPORAL_CHAIN_INVALID
E015  CONTEXT_BUILD_FAILED
E016  UNSUPPORTED_BELIEF
E017  COHERENCE_CONFLICT
```

错误处理必须支持“局部失败不阻断全流程”。

例如：

```text
Belief Resolver 失败
↓
Fact / Event 仍可返回
```

## 28. 架构关键设计决策 ADR

| ADR | 决策 |

## 30. 最终设计原则

### 原则一：相关性不等于状态

```text
Vector similarity
```

只能判断“相关”，不能决定“当前有效”。

### 原则二：事实不等于观点

```text
Fact ≠ Belief ≠ Intent
```

必须分别建模。

### 原则三：历史不应该因为更新而消失

```text
supersede
```

优先于直接覆盖。

### 原则四：时间排序不等于时间推理

需要从：

```text
timestamp sorting
```

升级到：

```text
Temporal Chain
```

### 原则五：摘要不能替代证据

```text
Summary → Source Memory → Evidence
```

必须可回溯。

### 原则六：LLM 应该表达，而不是替系统维护事实

最终架构保持：

```text
System owns Memory State
LLM owns Language
```
