## 1. 背景与目标

把已经过评估、模拟与指标验证的记忆方案（docs/00）落地为 **`dnamemory` Python 依赖库**。四条硬性要求：

1. **可被其他系统调用**：pip 安装、import 使用，公共 API v1 冻结；
2. **可嵌入其他系统**：进程内（默认）+ 可选 FastAPI 侧车 / MCP 服务；
3. **配置项在代码调用层**：零配置文件、零环境变量，构造级/调用级/回调级显式传入；
4. **业务逻辑严谨 + 全量回归**：不变量、事务、幂等、并发、审计；模拟实验 1-8 全部转 pytest 并保持与基线一致。

现状盘点：设计文档完整（00-08）；模拟 MVP 的 11 项能力中 9 项已有实验证据，2 项缺口（**访问控制行为**、**反射压缩**）在本计划 M4 补齐；库代码尚未开工。

## 4. 配置项转移清单（调用层配置）

原则：库内**不读配置文件、不依赖环境变量**；三级传入通道——构造级 `MemoryConfig`（frozen dataclass）、调用级方法参数、能力级回调注入（`clock`/`embedder`/`extractor`/`judge`）；默认值文档化，覆盖必须显式传入。

| 配置项 | 转移位置 | 默认值 |
|-------|---------|-------|
| 关系类型白名单 | `MemoryConfig.relations` | 14 类 |
| 来源可信级 | `MemoryConfig.source_rank` | profile=3, agent=2, chat=1 |
| 事件生命周期默认值 | `MemoryConfig.event_defaults`（按 kind） | transient 50/0.28，core 150/0.02 |
| 边/事实默认权重与置信度 | 方法参数 | 0.5/0.8，事实 0.7 |
| 检索默认参数 | `recall(k=, max_hops=, tol_days=)` | k=8, hops=2, tol=2 |
| RRF 融合常数 | `MemoryConfig.rrf_k` | 60 |
| 访问加固系数 | `MemoryConfig.access_boost` | (3.0, 6.0) |
| 矛盾确认阈值 | `MemoryConfig.conflict_confirm_threshold` | 0.8 |
| 时间路激活 | `query.time` 显式传入，库不注入 | — |
| 生命周期顺序 | `MemoryConfig.lifecycle_order` | active→archived→tombstoned→deleted |
| 评测参数（种子/噪声率/k/bootstrap） | `EvalConfig`（调用层） | seed=42, 35%, k=5, 200 次 |
| 时钟 | `clock` 回调注入 | `datetime.now` |

## 5. 业务逻辑严谨性

### 5.1 数据不变量（库内强制）

1. 事件时间只追加，历史不覆盖（修改走 versions）；
2. 生命周期只能按序迁移；合规删除允许任意→deleted 且必须带 reason；
3. protected 节点不可自动归档/墓碑（仅显式 forget）；
4. `0 ≤ weight/confidence/value_score ≤ 1`；`valid_at ≤ recorded_at`；`invalid_at > valid_at`；
5. 同 key 活跃事实至多一个胜者，其余 `superseded_by + invalid_at`；
6. tombstoned/deleted/过期数据永不进入任何召回路径（含语义路）。

### 5.2 事务 / 幂等 / 并发 / 审计

- 单条写入原子提交；`write_text` 批量结果整体事务，任一条失败回滚并返回失败明细；
- `idempotency_key` 去重（Agent 重试不产生重复记忆）；
- SQLite WAL + `busy_timeout=5000` + `BEGIN IMMEDIATE` + 库内单写锁；读独立连接；
- 所有写/改/删/撤销写审计日志；`tombstones` 为删除唯一入口，物理删除后审计保留。

## 7. 依赖与风险

### 7.1 依赖矩阵

```toml
[project]
name = "dnamemory"
requires-python = ">=3.10"
dependencies = []                        # 核心零强制依赖

[project.optional-dependencies]
vector = ["sqlite-vec>=0.1.6", "numpy>=1.24"]
server = ["fastapi>=0.110", "uvicorn>=0.29"]
mcp    = ["fastmcp>=1.0"]
pg     = ["psycopg[binary]>=3.1"]
dev    = ["pytest>=8", "httpx>=0.27"]
```

向量自动探测：加载 sqlite-vec 失败 → numpy 兜底 → 双路检索。

### 7.2 风险

| 风险 | 对策 |
|-----|-----|
| 拆包引入行为回归 | M1 第一步即跑实验 1-8，数值与基线逐项比对 |
| 配置面扩大导致调用复杂 | 默认值文档化，95% 调用方零配置 |
| 向量扩展平台缺失 | 三级回退（sqlite-vec → numpy → 双路） |
| API 冻结后演进受限 | v1 只含已验证能力；新能力走可选参数或 v2 方法 |
| 反射压缩依赖 LLM | 默认降级：确定性规则摘要（时间窗聚合）先上线，LLM 增强后置 |
| M5/M6 延误 | 不阻塞 MVP：M1-M4 独立交付 |

## 8. 关键决策记录（v2 重新梳理要点）

1. 里程碑从 P0-P3 重构为 **M0-M6**，每阶段有独立验收；
2. **MVP = M1-M4**，覆盖"优点审计"全部 11+2 项能力（含访问控制、反射压缩两个原缺口）；
3. LLM 拆解（M2）与语义路（M3）独立成里程碑，不再混在核心库中；
4. 服务化（M5）与发布（M6）后置，明确不阻塞 MVP；
5. 能力验收矩阵（§3）作为合入门禁的事实依据：每个能力必须有设计落点、实现里程碑与测试证据。
