## C1 配置与依赖注入（MemoryConfig）

**目标**：所有可变参数经调用层显式传入，零配置文件、零环境变量。

```python
@dataclass(frozen=True)
class MemoryConfig:
    relations: frozenset[str]              # 关系白名单（默认 14 类）
    source_rank: Mapping[str, int]         # 默认 {"profile":3, "agent":2, "chat":1}
    event_defaults: Mapping[str, LifecycleDefaults]  # 按 kind：life/decay_rate
    rrf_k: float = 60.0                    # RRF 常数
    access_boost: tuple[float, float] = (3.0, 6.0)   # (base, value_coef)
    conflict_confirm_threshold: float = 0.8
    lifecycle_order: tuple[str, ...] = ("active", "archived", "tombstoned", "deleted")
    max_hops_default: int = 2
    time_tolerance_days_default: int = 2
```

校验规则（构造时抛出 `ValidationError`）：
- `relations` 非空且全小写；`source_rank` 必须包含 `"profile"`；
- 所有 `0 ≤ 阈值/系数 ≤ 1`；`rrf_k > 0`；`lifecycle_order` 至少含 active/archived/tombstoned/deleted；
- 配置不可变：覆盖行为 = 构造新实例，不提供 setter。

## C2 存储层（SQLiteStore）

**目标**：进程内持久化，事务安全，单写多读。

DDL：方案 00 §4 五张表 + 新增 `audit_log`：

```sql
CREATE TABLE IF NOT EXISTS audit_log (
  id INTEGER PRIMARY KEY,
  op TEXT NOT NULL,            -- write/archive/tombstone/delete/version/confirm
  target_type TEXT, target_id INTEGER,
  reason TEXT, meta TEXT,
  at TIMESTAMP NOT NULL
);
```

幂等：`nodes.idempotency_key TEXT UNIQUE`、`facts.idempotency_key TEXT UNIQUE`（NULL 允许重复）。

PRAGMA：`journal_mode=WAL`、`busy_timeout=5000`、`foreign_keys=ON`。

事务与并发：
- `transaction()` 上下文管理器，`BEGIN IMMEDIATE`，配合库级写锁 `threading.Lock`；
- 写路径统一走 `transaction()`；读路径使用独立连接（`check_same_thread=False`）；
- `SQLITE_BUSY` 重试 3 次（50ms/150ms/450ms 退避），超时抛 `StorageError`；
- `:memory:` 模式：单连接 + 单写锁，禁止跨线程。

异常：约束违反 → `ValidationError`；记录不存在 → `NotFoundError`；写锁超时 → `StorageError`。

## C3 写入与 LLM 拆解

**结构化写入**（无 LLM 依赖，逐条原子）：

```python
add_event(name, ts, *, kind="meeting", value_score=0.5, protected=False,
          access_label="public", idempotency_key=None, meta=None) -> int
add_entity(name, *, kind="concept", description="", protected=False,
           access_label="public", idempotency_key=None) -> int
add_edge(a, b, rel, *, weight=0.5, confidence=0.8,
         valid_at=None, invalid_at=None, idempotency_key=None) -> int
add_fact(entity, key, value, *, source="chat", confidence=0.7,
         valid_at=None, idempotency_key=None) -> int
```

校验：`rel ∈ config.relations`；`0 ≤ weight/confidence/value_score ≤ 1`；`valid_at ≤ recorded_at`；`invalid_at > valid_at`；事件必须带 `ts`，实体必须不带。

**LLM 拆解入口**：

```python
write_text(text: str, *, meta: dict | None = None,
           extractor: Extractor | None = None) -> WriteResult
```

`Extractor.extract(text, meta) -> list[ExtractedMemory]`；`ExtractedMemory` 字段：

```python
{ type: "event"|"entity"|"edge"|"fact", name, kind?, ts?, value_score?,
  protected?, source?, confidence?, rel?, from?, to?, key?, value?,
  idempotency_key? }
```

批量事务：同批候选在单个事务内写入；**每条候选先经 Pydantic v2（PydanticAI 同源 schema）逐条强校验，不合格候选（字段缺失/端点不存在/关系类型非法）只丢弃自身并计入 `dropped`，合格候选照常写入**（LLM 输出容错，MVP 二轮实测 328 写入/39 跳过）；结构化单条写入仍保持原子性。默认 `extractor=None` 时 `write_text` 抛 `ValidationError`（提示先注入抽取器）。

## C4 检索（三路 + RRF + 过滤链）

路径激活：

| 路径 | 激活条件 | 打分 |
|-----|---------|-----|
| 时间路 | `query.time` 非空（库不自动注入） | `1/(1+天数差)` |
| 图谱路 | `query.topic` 或 `query.relation` 非空 | `(1/(hop+1))×weight×confidence×value_score` |
| 语义路 | `embedder` 已注入 且 `query.text` 非空 | bge-m3 稠密余弦相似度，`sim×(0.5+0.5×value_score)`，`sim ≥ dense_min_sim(0.55)`；向量存 `node_vectors` 表（dense 必写校验、sparse best-effort） |

过滤链（顺序固定）：
`lifecycle=active` → `invalid_at` 有效 → `access_label` 授权 → `RelationFilter` 硬过滤 → `node_types/kinds/time_range` → RRF 融合 → 排序 → top-k。

融合：`score(n) = Σ_path path_score(n)/(rrf_k + rank_path(n))`；并列按 `(score desc, ts desc, id asc)`。

```python
@dataclass(frozen=True)
class RecallQuery:
    text: str | None = None
    time: tuple[datetime, int] | None = None   # (锚点, 容差天数)
    topic: list[str] | None = None
    relation: RelationFilter | None = None     # {node, rel_type?}

@dataclass(frozen=True)
class RecallFilters:
    node_types: tuple[str, ...] | None = None
    kinds: tuple[str, ...] | None = None
    time_range: tuple[datetime, datetime] | None = None
    include_archived: bool = False
    access_labels: tuple[str, ...] | None = None  # None = public+private，sensitive 隐藏

@dataclass(frozen=True)
class MemoryHit:
    node_id: int; node_type: str; name: str; ts: datetime | None
    score: float; sources: tuple[str, ...]
```

## C5 生命周期

状态机：`active → archived → tombstoned → deleted`；非法迁移抛 `ValidationError`；`deleted` 允许任意状态进入（必须带 reason）。

- `step_day()`：仅 `active` 且非 `protected` 的节点扣减 `decay_rate`；life ≤ 0 → `archived` + 审计；
- `access(node_id)`：加固 `life += base + coef×value_score`（config.access_boost），更新 `last_access`；`protected` 节点只记访问不衰减；
- TTL：`facts/edges.invalid_at <= now` 一律过滤（含语义路）；
- `forget(target, reason, force=False)`：`tombstoned` + 审计；`protected` 节点默认拒绝，`force=True` 供合规删除使用；
- 查询 `include_archived=True` 可审计访问 archived，不恢复状态（恢复走 `restore()`）。

## C6 矛盾治理

```python
resolve_conflicts() -> list[ConflictDecision]
ConflictDecision = {kind: "resolved"|"confirm", node_id, fact_key,
                    winner: Fact, loser: Fact}
confirm(decision_id, choice: str)  # 用户裁决后执行
```

算法：
1. 按 `(node_id, fact_key)` 分组，取活跃事实（`invalid_at` 未过期且未墓碑）；
2. 排序键 `(source_rank[source], confidence, valid_at)` 降序；
3. 头两名同源且双置信 ≥ `conflict_confirm_threshold` → `confirm`（不自动裁决）；
4. 否则 `resolved`：胜者保留，其余 `invalid_at=now + superseded_by=胜者`；
5. 全部写入一个事务 + 审计。

## C7 访问控制

- `access_label ∈ {public, private, sensitive}`；
- 默认 `access_labels=None` → 只返回 public + private（**sensitive 默认隐藏，数据不删除**）；
- 显式 `access_labels=("sensitive",)` 才可见；`deleted` 永不返回；
- 合规删除：`forget(..., force=True)` → `deleted` + `tombstones` 审计保留；
- 恢复：`restore()` 只作用于 archived/tombstoned（deleted 不可恢复，走重建）。

## C8 反射压缩

- `reflect_monthly(year, month)`（确定性规则，M4 交付，LLM 增强在 M2 之后可替换）：
  1. 取该月 `active` 事件 → 生成摘要事件节点（value_score = 源事件均值×0.8）；
  2. 摘要节点 → 每条源事件 `summarizes` 边；
  3. 同 key 事实收敛：同一 `(node, key)` 活跃多条时按 C6 规则收敛，并在 `updates_to` 链上追加版本；
  4. 分层：生成簇节点（按主题实体），事件 `part_of` 簇，簇 `part_of` 摘要；
- 验证：`recall(topic=[主题], relation={node: 摘要, rel_type: "summarizes"})` 可定位源事件；`part_of` 可做层次展开。

## C9 指标与评测

```python
@dataclass
class EvalQuery:
    query: RecallQuery; truth: set[int]; label: str   # A/B/role/noise

def evaluate(dataset: list[EvalQuery], k: int = 5,
             mode: str = "dual", n_bootstrap: int = 200) -> EvalReport
```

指标：Recall@k、Precision@k、MRR、MAP@k、NDCG@k（公式同 docs/05 §2）；按 label 分层输出 + 总体 + bootstrap 95% CI；空真值查询剔除并单独统计覆盖率。

门禁（CI 每次合并）：`MAP@5 ≥ 0.90`、`Recall@5 ≥ 0.95`、噪声切片 `Recall@5 ≥ 0.65`、迁移回归 0 降级。

## C11 异常体系

```python
class MemoryError(Exception)
class ValidationError(MemoryError)   # 入参/不变量违反
class NotFoundError(MemoryError)     # 目标不存在
class ConflictError(MemoryError)     # 需要 confirm 或幂等冲突
class StorageError(MemoryError)      # 存储层失败（含锁超时）
```

错误码表：`E001` 未知关系类型；`E002` 数值域越界；`E003` 双时态顺序错误；`E004` 非法生命周期迁移；`E005` protected 拒绝自动遗忘；`E006` 目标不存在；`E007` 幂等键冲突；`E008` 待确认冲突；`E009` 存储忙；`E010` 抽取器未注入。
