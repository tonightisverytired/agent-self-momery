## 1. 目标与场景

为长期个人智能体（跨会话、跨月/年的个人 AI 助手）设计一套可落地的持久记忆系统，满足四类核心问题：

| 问题 | 定义 | 验收方向 |
|-----|-----|---------|
| 召回 Recall | 正确记忆被取回 | 双路/三路召回命中率 |
| 新鲜度 Freshness | 更新后使用最新版本 | 双时态 + 版本化 |
| 矛盾处理 Contradiction | 冲突时按策略取正确版本 | 可信源优先 + 确认机制 |
| 遗忘 Forgetting | 该消失的消失（过期/撤回/合规删除） | 生命周期状态机 + 墓碑 |

场景特征：单用户、本地优先、自然语言查询为主、时间模糊与主题模糊并存、隐私敏感、记忆量随时间线性增长。

## 2. 设计原则

### 2.1 采纳（来自 01/02/03 的合理内核）

1. **时间索引是一等公民**：所有事件节点带时间戳，支持"上周三发生了什么""这个决定之前发生了什么"。
2. **双路互补检索**：时间维与主题维互为兜底，一维模糊时另一维补救（保留抗遗忘公式作为工程上限参考）。
3. **受控遗忘**：价值评分 + 衰减率 + 生命周期状态机，防止记忆无限膨胀。
4. **不可变 + 版本化**：写入只追加，修改生成新版本，支持审计与回滚。
5. **写入时校验**：一致性校验与写入同步执行，不做事后补救。
6. **不删除的访问控制**：敏感记忆默认隐藏而非物理删除；合规删除走显式流程。
7. **分层组织**：节点粒度 + `part_of` 关系构成"原子→片段→簇→库"的多层导航。

### 2.2 修正

1. **遗忘从"频率优先"改为"价值优先"**：`value_score`（对用户的重要度）与访问频率分离；核心偏好/身份入保护区，永不衰减。
2. **矛盾处理从"新者胜"改为"双时态 + 可信源优先"**：`valid_at/recorded_at` 分离，来源可信级 profile > agent > chat；同源高置信冲突进入人工确认。
3. **语义检索从"关键词/图遍历"升级为三路召回**：时间窗口 + 图谱展开 + 向量相似，RRF 融合。
4. **四种记忆原子（A/T/C/G）降级为节点 kind 标注**：不强制四分类，允许多标签。

### 2.3 放弃

1. **"碱基对"具象概念**：氢键 2/3、A=T/G≡C、巩固=2→3、解离等全部废弃，替换为带类型关联边（见第 7 节）。
2. **"双链"作为数据结构**：T 链/S 链退化为"时间索引 + 语义索引"两个检索维度。
3. **10⁻⁹ 错误率表述**：LLM 记忆错误来自抽取与幻觉，用置信度 + 校验 + 评测管理，不承诺比特级指标。
4. **密码子/翻译等生物学隐喻**：检索排序用标准 rerank/RRF。

## 3. 总体架构

```
┌──────────────────────── 应用层 ────────────────────────┐
│  对话 / 任务 / 日程 / 文件输入        recall(query) 输出  │
└─────────────────────────┬─────────────────────────────┘
                          │
┌─────────────────────────▼─────────────────────────────┐
│                    治理层（Governance）                │
│  生命周期状态机 · 矛盾策略 · 访问控制 · 反射压缩 · 审计   │
├───────────────────────────────────────────────────────┤
│                    索引层（Index）                     │
│  时间索引（ts） │ 语义索引（embedding） │ 图索引（edges）│
├───────────────────────────────────────────────────────┤
│                    存储层（Store）                     │
│  nodes（事件/实体统一异构节点）                          │
│  edges（带类型关联边） · facts（双时态事实）             │
│  versions（版本审计） · tombstones（墓碑/删除记录）      │
└───────────────────────────────────────────────────────┘
```

三个语义层：

| 层 | 内容 | 载体 |
|---|-----|-----|
| 核心保护区 | 用户偏好、身份、长期目标，永不衰减，更新需确认 | `protected=1` 的节点 + facts |
| 情景层 | 一次对话、一次会议、一次操作 = 事件节点 | EventNode（带 ts） |
| 语义层 | 人物、项目、概念、技能、供应商 = 实体节点 | EntityNode（kind 细分） |

## 4. 数据模型

### 4.1 节点（nodes）

统一异构节点：事件与实体同表，用 `node_type` 区分，用 `kind` 细分。

```sql
CREATE TABLE nodes (
  id            INTEGER PRIMARY KEY,
  node_type     TEXT NOT NULL CHECK (node_type IN ('event','entity')),
  kind          TEXT NOT NULL,        -- 事件: meeting/decision/deploy/chat/...
                                      -- 实体: person/project/concept/skill/preference/vendor/...
  name          TEXT NOT NULL,        -- 事件摘要 或 实体名称
  description   TEXT DEFAULT '',
  ts            TIMESTAMP,            -- 仅事件：发生时间；实体为 NULL
  value_score   REAL NOT NULL DEFAULT 0.5 CHECK (value_score BETWEEN 0 AND 1),
  decay_rate    REAL NOT NULL DEFAULT 0.0,   -- 生命周期衰减率（protected 节点为 0）
  protected     INTEGER NOT NULL DEFAULT 0,  -- 核心保护区标记
  access_label  TEXT NOT NULL DEFAULT 'public',  -- public/private/sensitive
  lifecycle     TEXT NOT NULL DEFAULT 'active', -- active/archived/tombstoned/deleted
  last_access   TIMESTAMP,
  created_at    TIMESTAMP NOT NULL
);
CREATE INDEX idx_nodes_ts     ON nodes(ts);
CREATE INDEX idx_nodes_name   ON nodes(name);
CREATE INDEX idx_nodes_life   ON nodes(lifecycle, protected);
```

### 4.2 关联边（edges）

`edges` 取代旧"碱基对"，是系统唯一的关联形态：任意节点对之间的有向边，带类型、权重、置信度与双时态。

```sql
CREATE TABLE edges (
  id            INTEGER PRIMARY KEY,
  from_id       INTEGER NOT NULL REFERENCES nodes(id),
  to_id         INTEGER NOT NULL REFERENCES nodes(id),
  relation_type TEXT NOT NULL,        -- 见 4.4 枚举
  weight        REAL NOT NULL DEFAULT 0.5 CHECK (weight BETWEEN 0 AND 1),
  confidence    REAL NOT NULL DEFAULT 0.8 CHECK (confidence BETWEEN 0 AND 1),
  valid_at      TIMESTAMP NOT NULL,   -- 生效时间（事实成立的时间）
  invalid_at    TIMESTAMP,            -- 失效时间；NULL = 仍有效
  created_at    TIMESTAMP NOT NULL,   -- 记录时间
  last_access   TIMESTAMP,
  access_count  INTEGER NOT NULL DEFAULT 0,
  lifecycle     TEXT NOT NULL DEFAULT 'active'  -- active/tombstoned
);
CREATE INDEX idx_edges_from ON edges(from_id);
CREATE INDEX idx_edges_to   ON edges(to_id);
CREATE INDEX idx_edges_rel  ON edges(relation_type, lifecycle);
```

### 4.3 事实 / 版本 / 墓碑（facts、versions、tombstones）

```sql
CREATE TABLE facts (
  id            INTEGER PRIMARY KEY,
  node_id       INTEGER NOT NULL REFERENCES nodes(id),
  fact_key      TEXT NOT NULL,        -- 规范键，如 address / job / favorite_drink
  fact_value    TEXT NOT NULL,
  source        TEXT NOT NULL DEFAULT 'chat',  -- profile/agent/chat
  confidence    REAL NOT NULL DEFAULT 0.7,
  valid_at      TIMESTAMP NOT NULL,   -- 事实生效时间
  recorded_at   TIMESTAMP NOT NULL,   -- 事实记录时间
  invalid_at    TIMESTAMP,            -- 失效时间（过期/被取代）
  superseded_by INTEGER REFERENCES facts(id),
  tombstoned    INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_facts_key ON facts(node_id, fact_key, tombstoned);

CREATE TABLE versions (
  id            INTEGER PRIMARY KEY,
  node_id       INTEGER NOT NULL REFERENCES nodes(id),
  version       INTEGER NOT NULL,
  content       TEXT NOT NULL,
  created_at    TIMESTAMP NOT NULL,
  UNIQUE (node_id, version)
);

CREATE TABLE tombstones (
  id            INTEGER PRIMARY KEY,
  target_type   TEXT NOT NULL,        -- node/edge/fact
  target_id     INTEGER NOT NULL,
  reason        TEXT NOT NULL,        -- retracted/expired/consent_withdrawn/...
  tombstoned_at TIMESTAMP NOT NULL
);
```

### 4.4 关系类型枚举（初始集）

| relation_type | 方向语义 | 典型场景 |
|--------------|---------|---------|
| participates | 人 参与 事件 | "张总参与过哪些会议" |
| discusses | 事件 讨论 主题/项目 | "关于项目A的讨论" |
| mentions | 事件 提及 实体 | 闲聊提到某供应商 |
| occurs_with | 事件 伴随 事件/实体 | 同一时段关联 |
| precedes | 事件 先于 事件 | 因果追溯、时间线 |
| causes | 事件 导致 事件 | 根因分析 |
| depends_on | 技能/方案 依赖 概念 | 技能图谱 |
| similar_to | 概念 相似 概念 | 方案对比 |
| part_of | 节点 属于 上级节点/簇 | 层次导航 |
| prefers | 实体 偏好 事物/行为 | 用户偏好（保护区） |
| updates_to | 版本 更新为 版本 | 事实/记忆更新链 |
| contradicts | 事实 与 事实 矛盾 | 冲突标记（由校验生成） |
| summarizes | 摘要节点 概括 源节点 | 反射压缩 |
| step_of | 步骤 属于 流程 | 技能/流程知识 |

### 4.5 双时态约定

- `valid_at`：事实/关系在现实世界中成立的时间（用户 6 月搬家，搬家日期就是 valid_at）。
- `recorded_at / created_at`：系统记录该事实的时间（6 月 20 日才告诉助手）。
- 检索默认取 `valid_at <= now AND (invalid_at IS NULL OR invalid_at > now)` 的活跃版本。

## 5. 检索 API

### 5.1 签名

```python
@dataclass
class RelationFilter:
    node: str          # 实体名
    rel_type: str | None = None   # 关系类型过滤，None = 任意

@dataclass
class RecallQuery:
    text: str | None = None                            # 语义检索文本（调用方嵌入）
    time: tuple[datetime, int] | None = None           # (锚点时间, 容差天数)
    topic: list[str] | None = None                     # 实体/主题词
    relation: RelationFilter | None = None             # 角色/关系过滤

@dataclass
class RecallFilters:
    node_types: list[str] | None = None    # ['event','entity']
    kinds: list[str] | None = None
    time_range: tuple[datetime, datetime] | None = None
    include_archived: bool = False
    access_labels: list[str] | None = None

def recall(query: RecallQuery, filters: RecallFilters | None = None,
           k: int = 8) -> list[MemoryHit]:
    """三路召回 + RRF 融合。MemoryHit = (node_id, node_type, name, ts,
    score, sources, evidence)。"""
```

### 5.2 三路召回与融合

1. **时间路**：`ts` 落在 `(锚点 ± 容差)` 内的事件，得分 `1/(1+天数差)`。
2. **图谱路**：实体名/描述匹配 topic → 沿 edges 展开 ≤2 跳，事件得分 `1/(hop+1) × weight × confidence × value_score`。
3. **语义路**：query.text 嵌入后与节点向量做相似度，得分 = `sim × value_score`。

融合：对每路结果取排名，`score(n) = Σ_path 1/(60 + rank_path(n))`；若带 `RelationFilter`，先按该关系做硬过滤再做融合；同分按时间新旧排序。

**路径激活规则（MAP 实验发现）**：时间路仅在查询显式携带时间锚点（用户提到了时间）时激活；主题锚定查询不注入随机时间提示。否则无意义的时间路会挤占主题结果排序（实测使 B 类主题查询 MAP@5 从 0.960 降到 0.458）。

### 5.3 查询示例

```python
# 时间模糊："大概是上个月的项目预算会"
recall(RecallQuery(text="项目预算会", time=(now - 30天, 15)))

# 主题模糊："那个关于微服务的讨论"
recall(RecallQuery(topic=["微服务"], text="微服务讨论"))

# 角色过滤："张总参与过哪些项目？"
recall(RecallQuery(topic=["张总"],
                   relation=RelationFilter(node="张总", rel_type="participates")))

# 偏好查询（保护区）："我喜欢喝什么？"
recall(RecallQuery(topic=["咖啡"], relation=RelationFilter(node="咖啡", rel_type="prefers")))
```

## 6. 写入与治理管线

### 6.1 写入管线（同步）

```
输入流 → 1.抽取 → 2.价值打分 → 3.关联 → 4.一致性校验 → 5.写入+审计
```

1. **抽取**：LLM 从对话/文件/日程提取候选记忆（事件、事实、技能、偏好），给出建议节点类型与关系类型。
2. **价值打分**：`value_score = importance × persistence`；偏好/身份类自动 `protected=1, decay_rate=0`；一次性琐事低分。
3. **关联**：命名实体链接（同名复用现有节点），按语义选择 `relation_type`，写入 `valid_at/recorded_at`。
4. **一致性校验**：同 `(node, fact_key)` 的活跃事实冲突时，执行 6.3 矛盾策略。
5. **写入 + 审计**：全部追加；修改走 `versions`，不覆盖原文。

### 6.2 生命周期状态机

```
active ──(价值分衰减/长期未访问)──▶ archived（降权，检索默认不可见，可恢复）
active ──(用户"忘掉这件事")──────▶ tombstoned（检索彻底过滤，审计保留）
any ────(合规删除/撤回同意)──────▶ deleted（物理删除 + tombstones 记录）
```

- 模拟实现：节点携带生命周期预算（life），每日扣除 `decay_rate`，访问加固 `life += 3 + 6×value_score`；`protected` 节点不衰减。
- `archived` 不等于删除：通过 `include_archived=True` 可审计访问，可一键恢复。

### 6.3 矛盾策略（双时态 + 可信源）

| 情形 | 策略 |
|-----|-----|
| 来源可信级不同（profile > agent > chat） | 高可信胜出，低可信标 `invalid_at=now, superseded_by=胜者` |
| 同源且双方高置信（≥0.8） | 不自动裁决，返回"需确认"：同时呈现两个版本请用户定夺 |
| 低置信冲突 | 高置信胜出，低置信降权 |

该策略取代旧"时间戳新者胜"：用户闲聊口误（chat）不得覆盖用户档案（profile）。

### 6.4 访问控制与反射压缩

- `access_label ∈ {public, private, sensitive}`：敏感节点默认隐藏但保留（继承旧"甲基化"原则）；合规删除走 `deleted`。
- 反射压缩：每周/每月由 LLM 对事件层生成摘要节点，通过 `summarizes` 边指向源事件；同主题事实收敛为一条高置信记录（`updates_to` 链）。

## 7. 碱基对取舍评估

### 7.1 旧"碱基对"的问题清单

旧定义：`B = {(v_T, v_S, strength ∈ {2,3})}`，事件-实体跨链边，2=A=T 柔性 / 3=G≡C 刚性。

1. **关系语义丢失**："张总在项目A讨论预算"生成三条相同形态的碱基对，无法区分参与者/主题/对象，检索"谁参与了什么"只能靠全文。
2. **强度二分过粗**：2/3 两档把"关系类型"与"稳定性"两个正交维度绑死；真实场景需要连续权重、置信度、时效性。
3. **二部约束过强**：只能事件↔实体；事件↔事件（因果）、实体↔事实（偏好）、技能↔步骤（流程）、节点↔簇（层次）均无位可放，系统被迫并行多套边机制。
4. **生命周期挂错对象**：遗忘/巩固应作用于"记忆/事实"，碱基对却把生命周期挂在"连接"上；无事件锚点的偏好（"喜欢拿铁"）没有生命周期入口。
5. **工程冗余**：实现上就是带权外键；2/3 档位只是约束不是能力（模拟中"巩固"即 `if accesses>=5: strength=3`，换成连续权重更自然）。
6. **隐喻负担**：氢键、解旋、转录等术语增加理解与维护成本，且会误导实现者去"仿生"。

### 7.2 候选形态对比

| 维度 | 保留碱基对 | 带类型关联边（本方案） | 统一图模型（Zep/MemoriesDB） |
|-----|-----------|---------------------|---------------------------|
| 关系语义 | 无类型 | 14+ 类型枚举，可扩展 | 同左 |
| 强度表达 | 离散 2/3 | 连续 weight + confidence | 同左 |
| 结构约束 | 仅事件↔实体 | 任意异构节点对（有向） | 同左 |
| 生命周期 | 挂在边上 | 节点/边/事实分开管理 | 同左 |
| 双时态 | 无 | valid_at/invalid_at | valid_at/invalid_at |
| 行业对标 | 无直接对应 | ≈ Zep/Graphiti（时间感知图谱） | = MemoriesDB（三合一） |
| 迁移成本 | 0 | 低（映射规则见第 8 节） | 中（需重写语义层） |

### 7.3 结论

**抛弃"碱基对"具象概念，采用带类型关联边**。保留其两个合理内核：①跨维度关联必须显式存在（不能只靠向量）；②关联要有强度与生命周期。这两个内核由 `edges` 表完整承载，其余生物学包装全部去掉。

## 8. 迁移策略

### 8.1 旧数据 → 新模型映射

| 旧概念 | 新模型 |
|-------|-------|
| 碱基对 (event, entity, strength=2) | edge，weight=0.5，rel 按事件类型推断（会议→discusses，聊天→mentions，人员→participates） |
| 碱基对 (event, entity, strength=3) | edge，weight=0.9，rel 按核心事件类型推断（决策/部署→discusses/depends_on，技能→step_of） |
| T 链有向边（先于/后于） | precedes / causes 边 |
| S 链无向边（属于/关联/类似/依赖） | part_of / occurs_with / similar_to / depends_on 边 |
| 事件端粒 + 端粒酶 | 节点 life 预算 + value_score + decay_rate + 访问加固 |
| 甲基化标记 | access_label / protected |
| 修复（MMR） | 写入时一致性校验 + 6.3 矛盾策略 |
| 版本化写回 | versions 表 |
| 原子/片段/簇/库 | 节点 + part_of 边 |

### 8.2 迁移步骤

1. 按映射表将旧事件/实体/碱基对转为 nodes/edges（关系类型由事件类型与实体 kind 推断，可留待 LLM 复核）。
2. 旧查询语义回归：同一批查询在旧模型（碱基对集合遍历）与新模型（edges 检索）上运行，断言新结果事件集 ⊇ 旧结果事件集。
3. 模拟代码同步重构为关联边模型，保留四类验收实验。

## 9. 风险与边界

- **抽取质量**：记忆质量上限取决于 LLM 抽取（幻觉、漏抽）；用 `confidence` + 用户确认 + 评测控制。
- **关系枚举扩展**：初始 14 类不够时走白名单扩展，禁止任意字符串（防脏数据）。
- **双时态复杂性**：`valid_at` 需要写入时正确判定，可先用 `recorded_at` 兜底。
- **向量检索依赖**：语义路需要 embedding（本地可用 sqlite-vec / pgvector + bge 等），离线场景退化为双路。
- **规模假设**：单用户 ≤10⁶ 节点，SQLite/PostgreSQL 足够；更大规模换列式/分布式存储。
- **不承诺比特级错误率**：用评测基准（LongMemEval/LOCOMO 四维分项）衡量，不用 10⁻⁹ 表述。

## 10. 指标与评测（保证设计的度量体系）

### 10.1 指标分层与验收目标（模拟基线为合成数据 v2，2026-08-02）

| 层 | 指标 | 定义 | 模拟基线（双路） | 验收目标 |
|---|-----|-----|---------------|---------|
| 检索层 | Recall@5 | top5 含至少一个真值记忆的比例 | 1.000 | ≥ 0.95 |
| 检索层 | Precision@5 | top5 中真值占比 | 0.642 | ≥ 0.60 |
| 检索层 | MRR | 首个真值命中的位置倒数均值 | 0.958 | ≥ 0.90 |
| 检索层 | MAP@5 | 平均精度均值（按查询类型分层） | 0.928（95% CI [0.901, 0.957]） | ≥ 0.90 |
| 检索层 | NDCG@5 | 归一化折损累计增益（分级相关） | 0.945 | ≥ 0.90 |
| 检索层 | TwoHopRecall@k | 多跳查询两个目标都在 top k | 角色推导场景 = 1.0 | = 1.0 |
| 新鲜度 | Freshness | 冲突后使用策略胜者版本的比例 | 实验 5：profile 胜出 | ≥ 0.95 |
| 矛盾处理 | ContradictionCompliance | 按策略裁决/确认的比例 | resolved/confirm 均正确 | = 1.0 |
| 遗忘 | ForgettingCompliance | 撤回/过期记忆零泄漏 | TTL + 墓碑均过滤 | = 1.0 |
| 遗忘 | FalseForgetting | 保护区/核心记忆丢失率 | 300 天 0 丢失 | = 0.0 |

### 10.2 评测数据集策略（沿用 evaluate-rag 方法论）

1. **合成 QA**：从每条记忆抽取事实并生成"只由该记忆回答"的问题；模拟中真值确定性可得，生产环境由 LLM 生成 + 人工抽检。
2. **对抗性问题**：用相似但缺少答案的记忆做干扰，生成高难度查询（例如用"2008 年亏损"干扰"最大跌幅"）。
3. **真实查询回流**：定期从线上真实用户查询采样补入评测集，防止过拟合合成数据。
4. **按查询类型分层**：时间锚定（A）/ 主题锚定（B）/ 角色过滤 / 噪声（35% 污染）分别报告。

### 10.3 计分约定

- 空真值查询（记忆库中确实没有答案）：剔除出 MAP 计算，单独统计"覆盖率"，避免分母污染。
- k 按查询类型设定：单事实查找 k=3，综合/追溯查询 k=10，当前模拟统一 k=5。
- MAP 必须与 Recall@k 配对使用（防"排序好但漏召回"）；分级相关场景改用 NDCG@k。

### 10.4 MAP 可行性结论

**可行，且已在模拟中验证为检索层排序主指标**：双路 MAP@5=0.928（bootstrap 95% CI [0.901, 0.957]），分层显示 A 类时间锚定 0.987、B 类主题锚定 0.870；噪声（35% 污染）下 MAP@5 降至 0.569，说明 MAP 对提示质量敏感，可作为"抗遗忘噪声"的量化度量。详细探究见 [05-MAP可行性探究.md](./05-MAP可行性探究.md)。
