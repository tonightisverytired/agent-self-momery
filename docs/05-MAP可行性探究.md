# MAP 可行性探究：长期个人智能体记忆的检索排序指标

> 配套：[docs/00-长期个人智能体记忆系统方案.md](./00-长期个人智能体记忆系统方案.md)（第 10 节指标体系）
> 模拟：[simulation/dna_helix_memory_sim.py](../simulation/dna_helix_memory_sim.py) 实验 8
> 日期：2026-08-02

---

## 1. 背景

记忆系统的检索层需要一个能同时度量"召回"与"排序"的指标。Recall@k 只回答"有没有找回来"，不回答"排在第几位"；对个人智能体，排位直接决定注入上下文的内容与顺序。MAP（Mean Average Precision，平均精度均值）是信息检索领域的标准排序指标，本文件从定义、可行性条件、模拟实证三个层面评估它能否作为本项目检索层的核心指标。

## 2. 指标定义

对单个查询 q，真值集合为 R，检索系统返回排序列表 `[d1, d2, ...]`：

```
AP@k(q) = (1 / min(|R|, k)) × Σ_{i=1..k} [di ∈ R] × (命中数 up to i) / i
MAP@k   = (1 / N) × Σ_q AP@k(q)
```

配套指标（同一评测集、同一排序列表）：

| 指标 | 回答的问题 |
|-----|-----------|
| Recall@k | 相关记忆是否在 top k 里（覆盖率） |
| Precision@k | top k 里有多少是相关的（精确率） |
| MRR | 第一个相关记忆排多靠前（单事实查找） |
| NDCG@k | 分级相关下的排序质量 |
| MAP@k | 全部相关记忆的排序质量（综合） |

## 3. 可行性条件

MAP 要成立，必须满足以下条件；每一条都决定了"模拟里能算、生产里怎么算"：

| # | 条件 | 模拟中的实现 | 生产环境的实现 |
|---|-----|------------|--------------|
| 1 | 每个查询有真值标注 | 确定性真值（时间窗内事件 / 边链接事件） | 人工标注 + LLM 判题 + 抽样核对 |
| 2 | 排序列表稳定、无并列歧义 | RRF 分数可能并列 → 用时间倒序做确定性 tie-break | 同上，固定 tie-break 规则 |
| 3 | 空真值查询有明确约定 | 本模拟真值均非空 | 剔除出 MAP，单独统计覆盖率 |
| 4 | k 与查询类型匹配 | 统一 k=5 | 单事实 k=3，综合/追溯 k=10 |
| 5 | 样本量足够 | 每类 120 查询 + bootstrap CI | 每类 ≥ 100，CI 纳入报告 |
| 6 | 分层报告 | A/B 类分开统计 | 时间/主题/角色/噪声分层 |

## 4. 模拟实证（2026-08-02 最终运行）

评测集：240 查询（A 类时间锚定 120 条，B 类主题锚定 120 条），真值确定性可得；另加 120 条噪声查询（35% 污染）作压力切片。

### 4.1 整体指标（k=5）

| 路径 | Recall@5 | Precision@5 | MRR | MAP@5 | NDCG@5 |
|-----|---------|------------|-----|-------|--------|
| 仅时间路 | 0.500 | 0.189 | 0.500 | 0.500 | 0.500 |
| 仅图谱路 | 0.529 | 0.458 | 0.473 | 0.444 | 0.461 |
| 双路（时间+图谱） | **1.000** | **0.642** | **0.958** | **0.928** | **0.945** |
| 三路（+语义） | **1.000** | **0.689** | **0.998** | **0.993** | **0.996** |

### 4.2 分层 MAP@5（为什么混合值不够）

| 路径 | A 时间锚定 | B 主题锚定 |
|-----|-----------|-----------|
| 仅时间路 | 1.000 | 0.000 |
| 仅图谱路 | 0.019 | 0.870 |
| 双路 | 0.987 | 0.870 |
| 三路 | 0.987 | 1.000 |

混合 MAP@5=0.928 掩盖了两类查询的本质差异：时间路对主题查询完全无效（0.000），图谱路对时间查询几乎无效（0.019）。**分层报告是使用 MAP 的前提，否则无法定位是哪类查询拖了后腿。**

### 4.3 统计精度

- 双路 MAP@5 bootstrap 95% CI：**[0.901, 0.957]**（200 次重采样，240 查询）。
- 说明：240 查询下 MAP 估计已有可接受精度；生产评测建议每类 ≥ 100 查询并固定 seed 回归。

### 4.4 噪声压力切片（35% 污染）

| 场景 | MAP@5 | Recall@5 |
|-----|-------|---------|
| 无污染双路 | 0.928 | 1.000 |
| 35% 时间/主题污染 | 0.569 | 0.708 |

MAP 对提示质量高度敏感——这既是缺陷（需要报告噪声水平），也是价值（可以把"抗遗忘噪声能力"变成可量化指标）。

### 4.5 三个关键发现（直接影响项目设计）

1. **融合是 MAP 的放大器**：双路把 MAP 从单路 0.444~0.500 提升到 0.928，三路到 0.993；MAP 量化了"双链互补"的价值，不再只靠召回率讲故事。
2. **路径激活规则**：B 类查询若被注入随机时间提示，双路 MAP 从 0.960 跌到 0.458（无意义的时间路挤占主题排序）。设计结论：**时间路仅在查询显式带时间锚点时激活**——已写入方案文档 5.2 节。
3. **MAP 与 Recall 必须配对**：双路 Recall@5=1.000 但 MAP@5=0.928，说明"都找到了但顺序欠佳"；只报 Recall 会漏掉排序问题，只报 MAP 会漏掉漏召回。

## 5. 可行性结论

### 5.1 判定：可行，且推荐为检索层排序主指标

- **模拟环境**：真值确定性可得，MAP 可精确计算，分层 + CI 完整，无歧义。
- **生产环境**：需要维护"查询-真值记忆"标注集（合成 QA + 对抗性生成 + 真实查询回流），并按本文第 3 节六条约定执行。成本可控，收益是可定位的排序回归。

### 5.2 边界

- MAP 只度量**检索层**；新鲜度、矛盾处理、遗忘合规分别用 Freshness / ContradictionCompliance / ForgettingCompliance 度量，不能混入 MAP。
- 分级相关（"这条记忆比那条更相关"）场景改用 NDCG@k；MAP 默认二进制相关。
- 空真值查询不参与 MAP（剔除并报告覆盖率），否则无意义地压低分数。

## 6. 落地要求清单

1. 评测集：合成 QA（每记忆一条）+ 对抗性查询 + 每季度真实查询回流抽样。
2. 标注：真值由确定性规则 + LLM 判题生成，人工抽检 ≥ 5%。
3. 报告：按 A/B/角色/噪声分层输出 MAP@5/Recall@5/MRR/NDCG@5 + bootstrap CI。
4. 门禁：检索层任何改动（融合权重、关系类型、衰减参数）跑同一评测集，MAP@5 ≥ 0.90 且 Recall@5 ≥ 0.95 方可合入。
5. 噪声切片作为常驻回归：污染 35% 时 MAP@5 ≥ 0.50、Recall@5 ≥ 0.65。
