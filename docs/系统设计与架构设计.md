# dnamemory 系统设计与系统架构设计

> 版本：v2.0（2026-09-16）｜适用版本：0.8.0

## 1. 总体架构

分层设计，核心为纯 Python 库，服务与 CLI 均为薄壳：

```text
┌──────────────────────────────────────────────────────────┐
│ 接入层：CLI / FastAPI 侧车（30 端点）/ 静态后台（六页）  │
│         / FastMCP（10 工具）/ 第三方调用                  │
├──────────────────────────────────────────────────────────┤
│ 门面层：MemorySystem（公共 API v1，零配置）               │
├──────────────────────────────────────────────────────────┤
│ 领域层：retrieval（多路+RRF+重排）/ resolve（状态解析）   │
│         governance（生命周期/冲突/反射/消解）             │
│         temporal / coherence / context / impact_chain     │
│         extract（LLM 抽取 + 兜底）/ metrics（评测）        │
├──────────────────────────────────────────────────────────┤
│ 存储层：SQLiteStore（事务/幂等/审计/向量索引）            │
│ 适配层：Embedder / Reranker / Extractor / TimeBackend /    │
│         GraphBackend 协议                                 │
└──────────────────────────────────────────────────────────┘
```

服务层目录（0.8.0 起 `app/` → `server/`）：`server/api/`（app 工厂 + deps 鉴权 + routes_query/write/govern + schemas 校验 + serializers 序列化 + static 静态托管）、`server/mcp.py`、`server/main.py`、`server/web/`（零构建静态后台）。

## 3. 数据模型与存储

### 3.1 表结构

| 表 | 用途 |
|---|---|
| `nodes` | 事件与实体统一异构节点（node_type∈{event,entity}/kind/name/ts/value_score/access_label/lifecycle/life/decay_rate/protected） |
| `edges` | 带类型关联边（14 类 rel、weight/confidence、双时态 valid_at/invalid_at、lifecycle） |
| `facts` | 实体事实（key/value/source/confidence/双时态/superseded_by/tombstoned） |
| `beliefs` | 观点（subject/proposition/polarity/双时态/access_label） |
| `intents` | 意图（subject/proposition/status 状态机/双时态） |
| `impacts` | 影响（subject/dimension/direction/valence/magnitude/kind/evaluator/cause_event） |
| `evidence` | 证据（source_type/source_ref/conversation_id/message_id/trust_level） |
| `versions` | 节点版本链 |
| `tombstones` | 删除/合并墓碑（唯一删除入口） |
| `audit_log` | 全部写/改/删/合并/收敛审计 |
| `triggers` | 触发器（entity/bridge/scene/horizon 四类） |
| `patterns` | 个人长期模式（preference/behavior/belief/decision/impact/temporal） |
| `memory_links` | 高阶记忆链（before/after/overlaps/changes/reinforces/contradicts/supersedes/caused_by/summarizes） |
| `node_vectors` | 稠密+稀疏向量（dense 强校验，sparse best-effort） |
| `vector_index_meta` | ANN 索引元数据（按 model+dim 分区） |

### 3.2 生命周期状态机

```text
active ──衰减──▶ archived ──遗忘──▶ tombstoned ──合规──▶ deleted
   │ ▲             │ ▲                 │ ▲
   └─恢复──────────┘ └──恢复───────────┘ └──── 终态（唯一出口）
```

- 合法迁移白名单在 `store.LEGAL_LIFECYCLE`，非法迁移抛 E001；protected 节点遗忘需 force（E005）；
- `deleted` 不可恢复（E004）；每次非幂等迁移写审计；
- 合规删除（`forget(force=True)`）在同一事务内级联：节点 deleted、关联 fact tombstoned、关联 edge tombstoned、写墓碑与审计。

### 3.3 六类记忆对象（0.5.0 分层语义）

- **Event/Entity**：图谱节点，承载时间与关联；事实/观点/意图/影响/证据为独立维度表（非 node_type）；
- **Fact**：版本链语义——`superseded_by` 固化裁决，历史版本进入 historical_changes 不删除；
- **Belief**：观点演化链不覆盖历史，全部保留，memory_links 标注 supersedes/contradicts/changes/reinforces；
- **Intent**：独立状态机 active→completed/cancelled/expired/superseded；
- **Evidence**：可追溯，`inferred` 来源强制标注推断（不伪装为事实）；事实缺失证据可 abstain 不编造。

## 4. 检索管线

### 4.1 路径与融合

| 模式 | 路径 |
|---|---|
| `time` | 仅时间路 |
| `graph` | 仅图谱路 |
| `semantic` | 稠密路（无 embedder 时词面代理） |
| `dual` | 时间 + 图谱 |
| `triple` | 时间 + 图谱 + 稠密语义（默认） |
| `quad` | 时间 + 图谱 + 稠密语义 + 稀疏路 |

融合：每路独立排序，按 `score/(rrf_k + rank)` 累加（RRF，rrf_k=60）；并列时按 路径顺序（time<graph<semantic<sparse）→ node_id 升序。

### 4.2 阈值与打分

- 稠密路：余弦相似度 ≥ `dense_min_sim=0.55`，打分 `sim×(0.5+0.5×value_score)`；
- 稀疏路：bge-m3 lexical_weights L2 归一化余弦 ≥ `sparse_min_sim=0.25`，同型打分；
- 时间路：`1/(1+diff_days)`，容差 `tol_days=2`；
- 图谱路：实体种子 BFS（max_hops=2），`(1/(hop+1))×weight×confidence×value_score`；
- 重排：注入 reranker 后对候选池前 `rerank_top_n=20` 重排；异常/分数异常一律回退原序。

### 4.3 过滤与安全

`RecallFilters`：node_types / kinds / time_range / include_archived / access_labels；`deleted` 永不返回，`sensitive` 默认隐藏；访问控制语义在 `retrieval._access_allowed` 统一兜底，state 解析/图谱/context 全路径复用。

### 4.4 记忆 Runtime 管线（0.5.0）

```text
recall_context(query, query_time)
  1) QueryRouter 纯规则路由：current_state / history / timeline /
     change / why_change / semantic_recall（无 LLM 可运行）
  2) 候选扩展：主题实体 + 邻接 BFS + 时间窗口 + 语义
  3) MemoryStateResolver 状态解析：当前事实（superseded_by →
     source_rank → explicit_confirmation → confidence → freshness，
     同源高置信并列 → conflict 交人工裁决）、历史、未知（未来时）
  4) TemporalChainBuilder 时间链：稳定排序 + 链拼接
  5) EvidenceValidator 证据校验：缺失 → abstain 说明
  6) CrossDimensionCoherence 跨维度一致性检查
  7) ContextBuilder 组装 16 区块（预算裁剪）：query_type /
     current_state / historical_changes / recent_events / beliefs /
     intents / temporal_chains / evidence / conflicts / notes /
     causes / impacts / impact_chains / patterns / score / trace
```

当前事实由确定性规则裁决，不使用向量相似度；`inferred` 证据强制标注。

**查询在场地（0.8.0，只作用于推理类区块）**

`recall_context` 在第 3 步之后算一个「在场地」（`_query_scope`）：检索/Trigger
命中的节点与主体 + 与查询有词面相关性的事实 + 状态类问题
（current_state/history/timeline/change/why_change）下上下文事实所属的主体。
该作用域**只收窄推理类区块**：

| 区块 | 收口规则 |
|---|---|
| `causes` | 只解释本次上下文里**展示出来的事实**（或候选带出的事件），并受新预算 `causes=10` 约束（原实现取全库 `caused_by`、无上限） |
| `impacts` / `patterns` | 只保留主体在场地内的条目（原实现全库） |
| `impact_chains` | 记忆集合取「本次上下文实际展示的内容」+ 在场地内的观点/意图，单点链丢弃 |
| `temporal_chains` | 无在场地对象时不做链推导 |

状态层（fact/belief/intent）**保持全库确定性裁决**：原则是「相关性不等于状态」
（§30）——「我现在住哪里」这类问句与事实无词面重叠，按相关性收口会把正确答案
一起滤掉。因此无在场地对象时不是「返回空上下文」，而是照常给状态 + 一条
`notes`：「未命中相关记忆：下面是库中当前状态，不是对本次问题的回答」。

**冲突以组为单位**（0.8.0）：`FactResolver` 产出 `ConflictGroup(node_id, key,
canonical_key, fact_ids, values)`，组结构一路带到序列化层，下游只做格式转换不
再二次分组；`conflicts` 预算按**组数**计（按 fact 条数截断会把并列组腰斩成
「只有一个值」的假冲突）。

## 5. 治理机制

| 机制 | 行为 |
|---|---|
| 受控衰减 | 每日按 decay_rate 扣 life，≤0 归档；protected 零衰减；step-day 手动步进 |
| 价值加固 | `access()` 按 value_score 增加 life |
| 冲突治理 | 同 (node,key) 活跃事实按 source_rank→confidence→valid_at 排序，败者 `superseded_by` 胜者；同源高置信进入 confirm 确认流程 |
| 反射压缩 | 月度摘要节点（value_score=源均值×0.8，access_label 继承最高敏感级）+ summarizes 边 + 主题簇（事件 part_of 簇、簇 part_of 摘要） |
| 稳定压缩（0.6.0） | `compress_stable()` 跨月稳定记忆聚合，生成 stable 节点 |
| 模式提取（0.7.0） | 四条确定性规则（impact/temporal/preference/behavior），全部 source="inferred"，幂等（proposition 哈希键） |
| 影响链 | `derive_impact_links` 推导 impact 因果 links（幂等）；ImpactChainBuilder 构建混合节点影响链 |
| 实体消解 | `resolve_entities()` 同名合并（不同 access_label 不合并）、边/事实重挂、自边清除、重复节点墓碑；写入端点模糊匹配阈值 0.88 |
| 事实版本链 | `fact_history(entity, key)` 返回按 valid_at 排序的完整事实链 |

## 6. 向量索引与降级链

- 索引：sqlite-vec `vec0` 余弦虚拟表，按 `(model, dim)` 独立分区，存归一化稠密向量；
- 同步：`set_node_vectors` 提交后增量 DELETE+INSERT；meta 不匹配自动全量重建；
- 检索：`_dense_path` 优先 `search_vectors`，失败回退 numpy 暴力；numpy 缺失回退双路——任何一层失败不阻断召回，top-k 集合与 numpy 一致。

## 7. 服务化（0.8.0）

### 7.0 可插拔检索后端（0.4.0）

- `MemorySystem(time_backend=None, graph_backend=None)`：缺省时检索走内置 SQLite 直连路径，不经过协议派发；
- 注入 `PostgresTimeBackend` / `Neo4jGraphBackend` 后，对应路径改为调用后端，RRF/过滤/重排逻辑不变；
- 后端查询只读，写入仍走 SQLite；数据由 `sync_memory_to_postgres` / `sync_memory_to_neo4j` 预置；
- 选型见 [后端选型.md](./后端选型.md)。

### 7.1 FastAPI 侧车（30 端点，读写全能力）

| 组 | 端点 |
|---|---|
| 元数据 | `GET /health`、`GET /stats`（原始行数口径） |
| 查询 | `POST /recall`、`POST /context`（16 区块）、`POST /timeline`、`GET /memory/{id}/history`、`GET /memory/{id}/explain`、`GET /facts`、`GET /neighbors`（节点名精确匹配，含 rel/方向/权重）、`GET /graph` |
| 写入 | `POST /entities /events /facts /beliefs /intents /impacts /evidence /edges /write /batch`（全部返回 `{id}` 或 accepted/ids） |
| 治理 | `POST /forget /resolve-conflicts /confirm /resolve-entities /reflect /compress-stable /extract-patterns /derive-impact-links /step-day /restore` |

- 鉴权：全部 API 路由 `Depends(require_auth)`（Bearer，`secrets.compare_digest` 常量时间比较）；`GET /` 与 `/static/*` 无鉴权；
- 错误体统一 `{code, message}`（0.8.0 起平铺）；状态映射：E004/E006/E013→404，冲突→409，Embedding→502，Storage→503，时间链/一致性→422，校验→400/422；
- 校验：写入族 `extra="forbid"` + 枚举校验（14 rel / polarity / status / direction / valence / kind / source_type）；时间一律 ISO；
- 抽取器：默认有 `DEEPSEEK_API_KEY` 即启用「LLM 优先 + 失败兜底」链（write 自动注入当日日期，相对时间换算成 ts）；`--fallback-extractor` 强制确定性兜底（离线/测试）；`--bge-m3` 加载本地语义模型；CORS 默认仅本机（`DNAMEMORY_CORS_ORIGINS` 可扩）。

### 7.2 GET /graph（图谱快照，静态后台数据源）

- 参数：`limit=500`（1-5000，截断目标为边数）、`node_types`、`include_archived`、`access_labels`（默认 public,private）、`center`+`hops`（1-3）；
- 可见性：节点排除 tombstoned/deleted，archived 按参数；边要求 `lifecycle=active` 且 `invalid_at` 未过期且两端可见；
- 截断策略（保证图完整无悬空边）：非 center 模式按 weight 降序取前 limit 条边作种子 → 节点集 = 边端点 + 按度数补足（含孤立节点，超 target 才截）→ 最终边 = 两端都在节点集内的全部可见边；center 模式按节点名精确匹配 BFS（出+入）hops 层，未命中返回空图 + `center.matched=false`（不 404）；
- 响应：`nodes[]`（含 degree）/`edges[]`/`counts`（nodes_active/entities_active/events_active/edges_active + lifecycle/access/rel_counts 分布，**截断前全量统计**）/`recent_events`（ts 降序前 10，独立于截断）/`center`/`truncated`；
- 序列化：`_graph_node_dict/_graph_edge_dict` 在 serializers.py（唯一序列化实现处）。

## 8. 安全与错误码

- token 用 `secrets.compare_digest` 常量时间比较；token 由调用层/环境注入（库内不读环境变量）；
- 路由显式枚举，无路径拼接；SQL 全部参数化（索引表名仅由 int/白名单字符构造）；
- 敏感记忆：sensitive 默认隐藏、deleted 永不返回、合规删除物理保留但全路径不可见；
- 错误码体系（`dnamemory.errors` 异常类 code）：E000 通用 / E001 校验 / E006 不存在 / E008 冲突 / E009 存储 / E011 向量 / E012 记忆状态冲突 / E013 证据不存在 / E014 时间链无效 / E015 上下文构建失败 / E016 不支持的信念 / E017 一致性冲突；另有文本码随 ValidationError 消息：E002 数值域 / E003 双时态 / E004 不可恢复 / E005 protected 需 force / E010 缺抽取器。

## 9. 关键设计决策（ADR）

| 决策 | 结论 |
|---|---|
