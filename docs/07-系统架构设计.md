# 系统架构设计：dnamemory 依赖库

> 依据：[00-长期个人智能体记忆系统方案.md](./00-长期个人智能体记忆系统方案.md)（数据模型与治理）
> 前置评估：[06-依赖库化与嵌入可行性评估.md](./06-依赖库化与嵌入可行性评估.md)
> 状态：架构设计 v1.0（2026-08-03），对应实施阶段 P0-P3

---

## 1. 设计目标

1. 提供 `dnamemory` Python 包，作为**进程内依赖库**被其他系统 import 调用；
2. 同一内核支持三种嵌入形态：进程内库（默认）、FastAPI 侧车（`[server]`）、MCP 服务（`[mcp]`）；
3. 零强制外部依赖（标准库 SQLite 即开即用），向量与网络能力走可选 extras；
4. 与方案 00 数据模型、检索、治理、指标完全一致，评测门禁可回归。

## 2. 包结构与模块职责

```
dnamemory/
├── __init__.py          # 导出 MemorySystem / RecallQuery / MemoryHit；__version__
├── models.py            # Node/Edge/Fact/Tombstone/RecallQuery/RecallFilters/MemoryHit
├── store.py             # StoreBackend 抽象 + SQLiteStore（DDL、WAL、索引、事务）
├── retrieval.py         # 三路召回（时间/图谱/语义）+ 分数加权 RRF + 路径激活规则
├── governance.py        # 生命周期状态机、矛盾策略（source_trust）、审计、TTL、墓碑
├── extract.py           # Extractor/Embedder/Judge 回调协议 + 确定性默认实现
├── metrics.py           # Recall@k/MRR/MAP@k/NDCG@k/合规指标 + EvalReport + 评测运行器
├── adapters/
│   ├── server.py        # FastAPI 侧车（dnamemory[server]）
│   └── mcp_server.py    # FastMCP 服务（dnamemory[mcp]）
└── cli.py               # init / write / recall / forget / eval 命令（可选）
```

分层依赖：`models ← store ← retrieval/governance ← extract ← MemorySystem ← adapters/metrics`。`MemorySystem` 是门面类，所有外部调用只经过它。

## 3. 公共 API（v1 冻结）

```python
class MemorySystem:
    def __init__(
        self,
        backend: StoreBackend | None = None,      # 默认 SQLiteStore(path 或 ":memory:")
        embedder: Embedder | None = None,         # 注入向量化回调；None = 双路检索
        extractor: Extractor | None = None,       # 注入 LLM 抽取；None = 结构化写入
        judge: Judge | None = None,               # 矛盾确认与评测判题
        clock: Callable[[], datetime] | None = None,
    ): ...

    # 写入（结构化，无 LLM 依赖）
    def add_event(self, name, ts, *, kind="meeting", value_score=0.5,
                  protected=False, access_label="public", **meta) -> int: ...
    def add_entity(self, name, *, kind="concept", description="",
                   protected=False, access_label="public") -> int: ...
    def add_edge(self, a, b, rel, *, weight=0.5, confidence=0.8,
                 valid_at=None, invalid_at=None) -> int: ...
    def add_fact(self, entity, key, value, *, source="chat",
                 confidence=0.7, valid_at=None) -> int: ...

    # 写入（LLM 抽取入口）
    def write_text(self, text: str, *, meta: dict | None = None) -> WriteResult: ...

    # 检索
    def recall(self, query: RecallQuery, filters: RecallFilters | None = None,
               k: int = 8) -> list[MemoryHit]: ...

    # 治理
    def access(self, node_id: int) -> None: ...          # 价值加固
    def forget(self, target: str | int, *, reason: str) -> None: ...  # 墓碑
    def resolve_conflicts(self) -> list[ConflictDecision]: ...
    def version_of(self, node_id: int) -> list[VersionRecord]: ...

    # 评测
    def evaluate(self, dataset: EvalDataset, k: int = 5) -> EvalReport: ...
```

`RecallQuery` 与 `RecallFilters` 保持方案 00 第 5 节定义不变（text / time / topic / relation + node_types / kinds / time_range / include_archived / access_labels）。

## 4. 存储后端抽象

```python
class StoreBackend(Protocol):
    def connect(self) -> None: ...
    def execute(self, sql: str, params: tuple = ()) -> Cursor: ...
    def transaction(self) -> ContextManager: ...
    def close(self) -> None: ...
```

- `SQLiteStore`：默认实现，创建方案 00 第 4 节五张表；`PRAGMA journal_mode=WAL`、`busy_timeout=5000`、`foreign_keys=ON`。
- 线程模型：库内单写锁串行化写事务，读操作走独立连接（WAL 支持读写并发）；`:memory:` 模式仅限单线程。
- `PostgresStore`（P3）：同一 Protocol，DDL 兼容迁移，供多设备/共享场景。

## 5. 检索管线（路径激活规则固化）

```
recall(query) ──▶ 路径选择 ──▶ 三路并行打分 ──▶ 分数加权 RRF ──▶ 过滤/排序 ──▶ MemoryHit[]
```

| 路径 | 激活条件 | 得分 |
|-----|---------|-----|
| 时间路 | query.time 非空（用户显式提到时间） | 1/(1+天数差) |
| 图谱路 | query.topic 或 relation 非空 | (1/(hop+1))×weight×confidence×value |
| 语义路 | embedder 已注入 且 query.text 非空 | bge-m3 稠密余弦 × (0.5+0.5×value)，sim ≥ dense_min_sim(0.55) |

规则（来自实验 8 的 MAP 发现）：
1. 主题锚定查询不注入随机时间提示；时间路只在 `query.time` 显式给出时激活。
2. 融合用分数加权 RRF：`score(n)=Σ_path path_score(n)/(60+rank(n))`，低分噪声自然衰减。
3. 空真值查询不参与 MAP（评测层处理），检索层正常返回空结果。

## 6. 治理与生命周期

- 状态机：active → archived（降权可恢复）→ tombstoned（显式撤回）→ deleted（合规删除），全部落 `tombstones` 审计。
- 矛盾策略：`source_trust`（profile > agent > chat），同源双高置信转 `confirm`，策略可注入替换。
- 生命周期：`decay_rate` 每日衰减 + `access()` 价值加固；`protected` 节点不衰减。
- 反射压缩：`write_text` 生成的摘要节点通过 `summarizes` 边指向源事件（LLM 回调）。

## 7. 嵌入形态

### 7.1 进程内（默认）

```python
from dnamemory import MemorySystem
mem = MemorySystem(path="user_memory.db")
hits = mem.recall(RecallQuery(topic=["项目A"]))
```

零服务、零网络，适合 Agent 代码直接嵌入。

### 7.2 FastAPI 侧车（`pip install dnamemory[server]`）

`GET /recall`、`POST /write`、`POST /forget`、`GET /health`；默认绑定 `127.0.0.1`，token 鉴权，路径白名单。

### 7.3 MCP 服务（`pip install dnamemory[mcp]`）

FastMCP 暴露工具：`write_memory` / `recall` / `forget` / `resolve_conflicts`；任选 stdio 或 streamable-http 传输，供 Claude/Codex 等 MCP 客户端连接。

## 8. LLM 回调协议（无厂商绑定）

```python
class Extractor(Protocol):
    def extract(self, text: str, meta: dict) -> list[ExtractedMemory]: ...
class Embedder(Protocol):
    def embed(self, texts: list[str]) -> list[list[float]]: ...
class Judge(Protocol):
    def confirm(self, conflict: ConflictDecision) -> str | None: ...
```

默认实现：Extractor 为空（只接受结构化写入），Embedder 为 None（双路检索），Judge 返回 None（保持待确认状态）。外部系统按自己的 LLM 栈注入实现。

P0.5 将交付一个**可插拔的参考 Extractor**（OpenAI 兼容接口，API 凭据经构造参数由调用层管理，不读环境变量），输出符合 `ExtractedMemory` schema（事件/事实/技能/偏好候选 + 建议节点类型与关系类型 + confidence），并配套提示词模板、JSON 校验重试与抽取评测集。

## 13. 配置原则（配置项在代码调用层）

库内**零配置文件、零环境变量依赖**，全部可变配置经调用层显式传入：

| 通道 | 内容 |
|-----|-----|
| 构造级 | `MemoryConfig`（frozen dataclass）：关系白名单、来源可信级、生命周期默认值、RRF 常数、访问加固系数、矛盾确认阈值、状态机顺序 |
| 调用级 | 方法参数：`recall(k, max_hops, tol_days)`、`add_edge(weight, confidence)`、`write_text(meta)` |
| 能力级 | 回调注入：`clock` / `embedder` / `extractor` / `judge` |

默认值完整文档化，保证零配置可用；覆盖必须显式传入，不静默生效。配置清单与默认值见 [08-实施计划.md](./08-实施计划.md) 第 2 节。
