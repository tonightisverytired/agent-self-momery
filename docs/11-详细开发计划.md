## 2. 需求落点表（03 §六 + 05 §4.5 → 设计/实现/验收）

| 需求 | 落点 | 实现位置 | 验收 |
|-----|-----|---------|-----|
| 补件1：语义向量第三维 | 三路召回（时间/图谱/语义）+ RRF 融合排序 | retrieval.py（M3 接真实 embedding，M1 用词面重叠代理） | 三路 MAP ≥ 双路 |
| 补件2：偏好/身份保护区 | `protected=1` 节点：不衰减、更新需确认、版本化 | models/memory/governance | 保护区 300 天存活；更新走 confirm 流程并生成 versions |
| 补件3：反射与压缩 | 月度总结 / 习惯洞察 / 项目脉络 → 高层节点（summarizes/updates_to/part_of） | governance.reflect_monthly（M4 规则先行 + LLM 接口预留） | 摘要正确链接源事件；分层查询可用 |
| 改策略：价值优先遗忘 | `value_score = importance × persistence`；核心事实/偏好/承诺永不衰减（仅归档降权）；显式"忘掉"→墓碑；撤回→真删除 | models/memory/governance | 低价值临时记忆归档、高价值核心记忆存活 |
| 双时态 + 可信源 | `valid_at/recorded_at` 分离；profile > agent > chat；同源高置信 → confirm | models/store/governance | 实验 5 场景通过 |
| 四维评估 | 召回/新鲜度/矛盾/遗忘分项指标，LongMemEval/LOCOMO 作为远期基准 | metrics.py + 门禁 | §5 门禁表 |
| 发现① 融合是放大器 | 双路/三路 MAP 作为核心指标，量化互补价值 | metrics/CI | 双路 MAP ≥ 0.90、三路 ≥ 双路 |
| 发现② 路径激活规则 | 时间路仅在 `query.time` 显式给出时激活；B 类查询不注入时间 | retrieval.py | 回归：B 类注入随机时间会导致 MAP 下跌的测试反向锁定 |
| 发现③ MAP 与 Recall 配对 | 门禁同时报告 Recall@5 与 MAP@5，两者任一不过即失败 | CI 门禁 | Recall≥0.95 且 MAP≥0.90 |
