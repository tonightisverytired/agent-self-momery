# 规模化检索方案（暴力检索治理）

> 日期：2026-08-05｜适用版本：0.4.0
> 依据：后端对比验证（20k/100k/250k 边实测）、docs/开发计划-可插拔后端.md

## 1. 问题：现在的"暴力"在哪里

每次 `recall` 的四个路径都存在全量扫描：

| 路径 | 现状 | 量级表现（实测） |
|---|---|---|
| 稠密语义路 | numpy 暴力兜底；有 sqlite-vec 索引时仍取 `k=全部节点` 再阈值过滤 | 100k 节点时索引退化为全量 |
| 图谱路 | 每次查询把全部边读进 Python 再 BFS | 25 万边 p50=397ms |
| 时间路 | 每次查询全表扫描计算天数差 | 10 万事件 p50=5.3ms（尚可，但随 N 线性） |
| 词面语义路 | 全节点 token 包含扫描 | 线性，无索引 |

## 2. 解决路线（按优先级）

### 2.1 稠密路：真 ANN top-k（已实施）

- `_dense_path` 不再取 `k=全部节点`，改为 `ann_k = min(N, max(config.dense_ann_top_k, k×20))`（默认 `dense_ann_top_k=1000`）；
- 阈值过滤仍在 top-k 候选上执行；N ≤ 5000 时继续 numpy 全量保证精确召回（小批量零影响）；
- 索引缺失且 N 超阈值时按配置决定：默认回退 numpy（小库），大库建议强制索引（文档提示）。

### 2.2 图谱路：邻接缓存（已实施）

- `SQLiteStore` 维护惰性邻接表 `adjacency(now)`：首次构建 O(E)，之后命中缓存 O(1)；
- 写入事务提交后 `_data_version += 1`，邻接缓存自动失效重建；
- `_graph_path` 改为基于邻接表的 BFS + 打分（语义与旧实现逐位一致）；
- 十万边以上建议注入 `GraphBackend`（Neo4j/Postgres），见 [后端选型.md](./后端选型.md)。

### 2.3 时间路：SQL 预筛（已实施）

- 先用 `ts BETWEEN lo AND hi`（窗口放宽 ±(tol+2) 天）走 `idx_nodes_ts` 缩小候选；
- 再用 Python 精确复算 `abs((ts-t0).days) <= tol` 与打分，保证语义与旧实现一致；
- 混合时区格式通过放宽窗口 + 精确过滤兜底，不产生假阴性。

### 2.4 后续（未实施，按需排期）

| 项 | 说明 |
|---|---|
| FTS5 中文分词 | 词面语义路改用 FTS5（trigram/tokenizer），替代全表扫描 |
| 元数据缓存 | `fetch_nodes/fetch_node_vectors` 按 `_data_version` 缓存，减少每查询重复全表读 |
| 索引缺失强制策略 | 大库（N>10 万）无向量索引时拒绝稠密路或显式告警 |
| 分片/归档 | 时间分片（按月/年表）+ 归档表，时间路只扫相关分片 |
| 规模化 CI 门禁 | 生成 10 万节点合成库，断言 recall p50 延迟预算（稠密<50ms、图谱<20ms、时间<20ms） |

## 3. 验收与回退

- 既有 56 例 pytest 全绿（含 P2 检索、P3 索引、后端集成）；
- 对拍：邻接缓存图路与旧实现结果逐位一致；时间预筛与旧实现逐位一致；ANN top-k 在小库（N≤5000）与 numpy 结果一致；
- 任一路径行为变化导致指标下降（门禁/中文能力评测）即回退该优化。
