# 开发计划：可插拔后端接口（TimeStore / GraphStore）

> 日期：2026-08-05｜版本：v1.0（计划，待批准后实施）
> 依据：[评估报告-Postgres与Neo4j替换.md](./评估报告-Postgres与Neo4j替换.md) §5/§5.1

## 1. 目标与边界

**目标**：把"时间链"与"空间链"的存储/检索解耦为可插拔后端接口，支持 Postgres（时间链）与 Neo4j（空间链，远期可选），同时**保证默认小批量路径零抽象开销**。

**边界（本计划不包含）**：

- 不替换默认 SQLite 实现，不做整体后端重构；

> **2026-09-17 补记**：本文规划的是**检索后端**（`TimeBackend`/`GraphBackend`，
> 只读查询加速）。另有一条**存储后端**轴已落地：`PGStore` 让 PostgreSQL 可作为
> 主存储（读写全路径、`dsn=` 配置开关、默认仍 SQLite）。两条轴正交，可分别启用；
> 注意两者的 schema 不通用（检索后端是 5 列精简表 + `DROP` 重建）。详见
> [Postgres后端使用手册](Postgres后端使用手册.md) 与 [后端选型](后端选型.md) §1 的说明。
- 不引入运行时配置/环境变量自动选型（保持零配置原则），后端由调用方显式注入；
- Neo4j 本期只做接口与适配器骨架 + 对拍验证，是否正式接入由数据规模决定；
- 不改变公共 API 的现有行为与默认参数。

## 2. 关键设计约束（来自验证发现）

1. **默认路径零开销**：`MemorySystem` 新增可选参数 `time_backend=None`、`graph_backend=None`；为 None 时检索走现有 SQLite 直连路径，不经过任何协议派发或额外函数调用；
2. **按需启用**：只有注入后端时才走适配器；
3. **打分语义一致**：后端适配器返回与现有路径相同的 `{node_id: score}` 字典；RRF 融合、过滤链、并列规则集中在 `governance.recall`，后端不做业务排序；
4. **小批量不引入**：文档化决策表——默认（单进程、边 < 5 万）使用内置 SQLite；仅当需要多进程共享、10 万级以上时间链、或深多跳图查询时，才显式注入 Postgres/Neo4j 后端。

## 3. 接口设计（决策完整）

```python
# dnamemory/backends/base.py
class NodeRef:            # 后端返回的最小引用
    node_id: int
    score: float

class TimeBackend(Protocol):
    """时间链后端：按时间窗返回事件候选及原始分。"""
    def time_window(self, lo, hi, filters) -> dict[int, float]: ...

class GraphBackend(Protocol):
    """空间链后端：从实体种子出发做 max_hops 遍历，返回事件候选及原始分。"""
    def traverse(self, seed_ids: list[int], max_hops: int,
                 rel_filter: str | None, filters) -> dict[int, float]: ...

class SQLiteTimeBackend:   # 默认路径的适配封装（可选，默认不启用）
class SQLiteGraphBackend:
class PostgresTimeBackend: # 阶段 1 交付
class Neo4jGraphBackend:   # 阶段 2 交付（可选）
```

注入方式：

```python
MemorySystem(time_backend=PostgresTimeBackend(dsn=...),
             graph_backend=Neo4jGraphBackend(uri=..., auth=...))
```

兼容规则：`time_backend/graph_backend` 均为 None 时，`MemorySystem.recall` 走现有代码路径（零改动）；任一非 None 时，`governance.recall` 的对应路径改为调用后端，其余路径（RRF/过滤/重排）不变。

## 4. 分阶段实施

### 阶段 0：接口与回归基线

- 新增 `src/dnamemory/backends/` 包与协议定义；
- 为默认路径增加**性能回归用例**：断言"未注入后端时 recall 延迟/调用路径与现状一致"（例如 mock 后端派发计数为 0）；
- 验收：pytest 59/59 保持通过，默认路径代码零行为变化。

### 阶段 1：Postgres 时间链后端

- 实现 `PostgresTimeBackend`（psycopg，`pg` extra，复用 `tools/pg_migrate.py` DDL，`nodes.ts` 索引）；
- 正确性对拍：`tools/backend_compare.py` 扩展或复用，断言 Postgres 时间结果集与 SQLite 一致；
- 性能基准：5k / 20k / 100k 事件三档，记录到 `simulation/backend_compare_result.json`；
- 验收：对拍全 true；注入后 `recall` 时间路结果一致；默认路径延迟不劣化。

### 阶段 2：Neo4j 空间链后端（可选）

- 实现 `Neo4jGraphBackend`（`neo4j` 驱动，独立可选依赖，不进入默认 extras）；
- Cypher 遍历 `-[*1..max_hops]-`，标签/索引按 `backend_compare.py` 已验证的方式；
- 正确性对拍 + 性能基准（10 万边、hop 2/3）；
- 验收：结果集与 SQLite BFS 一致；文档标注 GPLv3 与运维成本。

### 阶段 3：选型文档与收尾

- 新增 `docs/后端选型.md`：决策表（规模/并发/深跳 → 推荐后端）、注入示例、性能数据；
- 更新需求设计（FR-13 说明）、系统设计与架构设计（后端抽象层）、功能清单、开箱即用手册；
- 版本号维持 0.3.x 内新增（或 0.4.0，由实施时决定）。

## 6. 验收标准

1. `MemorySystem()` 不带后端参数时，行为与 0.3.0 完全一致（59/59 + 门禁 + 默认路径零派发）；
2. 注入 `PostgresTimeBackend` 后，时间路结果与 SQLite 一致；
3. 注入 `Neo4jGraphBackend` 后，空间路结果与 SQLite BFS 一致（若实施阶段 2）；
4. 文档（后端选型 + 四份正式文档）更新完成；
5. 关键发现写入评估报告 §5.1，开发按此原则执行。
